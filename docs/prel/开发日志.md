# 阶段二开发日志

本文记录第一阶段合入 `main` 之后，进入 `dev` 的阶段二改动。范围以
`main` 上第一阶段提交 `59ccdd63` 之后的 `dev` 历史为准，截止到
`zqh-fix-cyclictest-final` 合入 `dev`；`ltp`、`ltp-new` 等旁支上的试验性开发不纳入本文。

## 1. 测试启动与运行顺序

阶段初期的主要问题是测试脚本能够进入用户态，但因为根文件系统里没有统一的
`/bin/sh`、`/lib/...` 或 `/lib64/...`，脚本、动态链接器和 busybox applet 经常在启动阶段失败。

处理方向是让内核侧兼容评测镜像的目录布局：

- 对 shell 脚本执行路径做解析，优先使用当前 ABI 目录下的 busybox，例如 `/glibc/busybox sh` 或 `/musl/busybox sh`。
- 对 ELF `PT_INTERP` 中的 `/lib`、`/lib64`、`/usr/lib`、`/usr/lib64` 路径做 ABI 根目录 fallback。
- 对 musl 的 `ld-musl-*.so.1` 场景增加 fallback：如果对应文件不存在，但 `/musl/lib/libc.so` 存在，则使用 `libc.so` 作为动态链接器。
- 对缺失的 busybox applet 做有限 fallback，覆盖 `mkdir`、`rmdir`、`sleep`，后续扩展到 `kill`、`ls`、`which`。

阶段中通过 `src/init/init.sh` 调整过 glibc/musl 顺序、LTP 跳过策略和 lmbench/cyclictest profile，
用于定位评测耗时和阻塞点。该脚本仍由 `src/init/main.rs` 通过 `include_str!` 内嵌进 init 程序，
因此最终保留脚本入口；`zqh-fix-cyclictest-final` 合入后，默认 `TEST_PROFILE` 切到 `cyc-musl`，
用于优先验证 LoongArch musl cyclictest 路径。

## 2. 动态链接与 execve 状态清理

`glibc`/`musl` 动态程序的启动问题集中在两层：

- 内核 ELF loader 需要找到 `PT_INTERP` 指定的动态链接器。
- 动态链接器启动后还会继续通过用户态路径查找共享库。

阶段二对 loader 的解释器路径做了 ABI 感知处理，避免 `/lib/ld-linux-*`、
`/lib64/ld-linux-*` 或 musl `ld-musl-*` 因根目录布局不同而无法启动。
同时在测试脚本路径解析后再判断 ABI 目录，避免从脚本相对路径启动时选错 glibc/musl fallback。

`execve` 还补充清理了 `robust_list_head`。原因是 glibc 初始化会注册 robust list，
但 `execve` 替换地址空间后旧地址已经失效；若新程序在重新注册前退出，退出路径读取旧地址会触发
`BadAddress`。现在 `execve` 会同时清理 `clear_child_tid` 和 `robust_list_head`。

## 3. 文件系统、mmap 与 COW

文件和内存映射方面的主要改动包括：

- `sys_mount` 接受 `vfat` 类型，避免部分测试挂载 vfat 时直接返回 `ENODEV`。
- 文件解析路径在找不到有限 busybox applet 时，可以 fallback 到当前 ABI 目录下的 busybox。
- `mmap` 的非固定地址搜索会先规整低于用户地址空间 base 的 hint，避免无意义地从非法 hint 搜索。
- 文件页缓存 mmap 页补零，避免短文件或页尾未初始化内容暴露给用户态。
- COW frame 引用计数从 `u8` 扩到 `u16`，并优化 fork/clone 时的引用计数更新，缓解 hackbench 等压力下的引用计数溢出和锁开销。

这些改动主要面向 basic、iozone、lmbench、cyclictest/hackbench 压力场景中的文件映射和进程复制问题。

## 4. wait、信号与进程可见性

LoongArch 和部分 shell 测试里曾出现 `waitpid: Interrupted system call` 循环。
阶段二调整了 `wait4/waitpid` 的阻塞路径：被唤醒后先重新检查 zombie 子进程，
只有存在非 `SIGCHLD` 的未屏蔽信号时才返回 `EINTR`。这样子进程退出导致的 SIGCHLD 不会盖过可回收的 wait 结果。

信号发送路径也处理了一个 busybox 相关场景：当进程已退出但仍作为 zombie 留在进程树中时，
`kill`/shell 预检不应因为只查 live `ProcessData` 而误报 `ESRCH`。

`/proc/[pid]/stat`、`getrusage`、`times`、CPU clock 查询等路径改用 `try_borrow` 读取线程时间，
避免在 timer/poll 路径已持有可变借用时 panic。

## 5. poll/select、pipe 与时间 syscall

I/O 多路复用路径做了性能和语义收敛：

- `select/pselect` 先直接轮询一次所有 fd，已有 ready fd 时立即返回。
- 只有确实没有事件时才构造等待集合并进入 `poll_io`。
- 每轮等待前清空用户 fd_set，再只写回 ready fd，避免旧结果残留。
- `pipe` 的读写先尝试一次快路径，只有 `WouldBlock` 时再进入阻塞轮询。

时间 syscall 改动包括：

- `clock_gettime`、`gettimeofday` 直接从纳秒值构造 `timespec/timeval`，减少中间转换。
- `clock_getres` 返回 1ns 精度。
- CPU time 路径在借用冲突时返回错误或默认值，避免内核 panic。

这些改动主要服务于 lmbench、libcbench、busybox shell 管道和 cyclictest 的轮询/计时行为。

## 6. 调度 syscall 与 cyclictest

`cyclictest` 需要更完整的 Linux 调度接口。阶段二新增或补齐了：

- `sched_getscheduler`
- `sched_setparam`
- `sched_setscheduler`
- `sched_getparam`
- `sched_setattr`
- `sched_getattr`
- `sched_get_priority_max`
- `sched_get_priority_min`
- `sched_rr_get_interval`

线程结构中增加了 Linux 兼容的 `sched_policy` 和 `sched_priority` 字段。
当前实现主要保存并回报策略/优先级，支持 `SCHED_NORMAL`、`SCHED_FIFO`、`SCHED_RR` 的基本范围约束，
并不等价于完整 Linux 实时调度器。

`zqh-fix-cyclictest-final` 合入后，还对 LoongArch musl 的部分调度 syscall stub 做了运行时 patch。
原因是该 musl 镜像中的相关 stub 不能直接触发期望的 syscall 路径，导致 musl cyclictest 卡住。
内核仅在 LoongArch 且解释器解析到 `/musl/lib/libc.so` 时检查预期 stub 前缀并打补丁，避免影响其他 ABI。

## 7. LoongArch 平台稳定性

LoongArch 平台侧主要修复 timer 和启动映射：

- QEMU 运行 LoongArch 时改用 ELF 作为 kernel 输入。
- LoongArch 高内存 base 调整到 `0x9000_0000`。
- 启动页表对 `0x8000_0000..0xc000_0000` 改为 2M 页映射，避免单个 1G block 带来的映射粒度问题。
- timer 改为周期模式并避免反复关闭/开启 countdown timer，规避 QEMU 下清掉 pending timer 后定时器停住的问题。
- IRQ 路径在调用 handler 前清除 timer interrupt，避免 handler 重新 armed timer 后的新中断被错误清掉。
- 初始化中断时先设置第一次 timer deadline，再开启 IRQ。
- LoongArch 用户态中断返回时主动 `yield_now`，降低长时间占用导致的调度延迟。

这些改动主要对应 LoongArch basic/busybox、cyclictest 以及后续压力测试中的卡住和计时问题。
